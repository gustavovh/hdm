1. RESUMEN EJECUTIVO
================================================================================

El Sistema de Gestión de Presupuestos HDM es una aplicación web completa para
la gestión, seguimiento y análisis de presupuestos comerciales. Permite a
vendedores crear y gestionar presupuestos mientras que los administradores
pueden supervisar, aprobar y analizar la performance del equipo.

CARACTERÍSTICAS PRINCIPALES:
-----------------------------
✓ Gestión completa de presupuestos con múltiples estados
✓ Sistema de seguimiento con timeline de actividades
✓ Recordatorios y alertas automáticas
✓ Análisis de performance por vendedor
✓ Evaluación de KPIs y métricas de conversión
✓ Catálogo de productos con imágenes
✓ Sistema de aprobación de descuentos
✓ Generación automática de PDFs
✓ Envío de emails con notificaciones
✓ Exportación completa a Excel
✓ Seguridad con Row Level Security (RLS)
✓ Auditoría completa de acciones

USUARIOS DEL SISTEMA:
---------------------
- Vendedores: Crean, gestionan y hacen seguimiento de presupuestos
- Administradores: Supervisan, aprueban y analizan performance

TECNOLOGÍAS UTILIZADAS:
-----------------------
- Frontend: React + TypeScript + Vite
- Base de Datos: Supabase (PostgreSQL)
- Autenticación: Supabase Auth
- Storage: Supabase Storage
- PDFs: jsPDF + jsPDF-AutoTable
- Estilos: Tailwind CSS
- Iconos: Lucide React

4. BASE DE DATOS
================================================================================

4.1. TABLAS PRINCIPALES
-----------------------

USERS (Usuarios del sistema)
----------------------------
- id: uuid (PK)
- email: text (unique)
- full_name: text
- role: text (vendedor, admin)
- active: boolean
- created_at: timestamptz
- updated_at: timestamptz

PRESUPUESTOS (Cotizaciones)
---------------------------
- id: uuid (PK)
- codigo: text (unique, auto-generado)
- vendedor_id: uuid (FK → users)
- cliente_nombre: text
- cliente_email: text
- cliente_telefono: text
- cliente_ruc: text
- cliente_direccion: text
- concepto: text
- observaciones: text
- estado: text (BORRADOR, PRESENTADO, ACEPTADO, FACTURADO, ANULADO)
- moneda: text (PYG, USD)
- total_neto: numeric
- descuento_porcentaje: numeric
- descuento_monto: numeric
- total_con_descuento: numeric
- iva_monto: numeric
- total_final: numeric
- vigencia_dias: integer
- condiciones_pago: text
- fecha_presentacion: timestamptz
- fecha_aceptacion: timestamptz
- fecha_facturacion: timestamptz
- numero_factura: text
- clonado_desde: uuid (FK → presupuestos)
- created_at: timestamptz
- updated_at: timestamptz
- deleted_at: timestamptz

PRESUPUESTO_ITEMS (Líneas de presupuesto)
-----------------------------------------
- id: uuid (PK)
- presupuesto_id: uuid (FK → presupuestos)
- producto_id: uuid (FK → productos, nullable)
- descripcion: text
- cantidad: numeric
- precio_unitario: numeric
- subtotal: numeric
- orden: integer

PRESUPUESTO_IMAGENES (Imágenes adjuntas)
----------------------------------------
- id: uuid (PK)
- presupuesto_id: uuid (FK → presupuestos)
- imagen_url: text
- nombre_archivo: text
- orden: integer
- created_at: timestamptz

PRESUPUESTO_ACTIVIDAD (Timeline de actividades)
-----------------------------------------------
- id: uuid (PK)
- presupuesto_id: uuid (FK → presupuestos)
- usuario_id: uuid (FK → users)
- tipo_evento: text (creado, cambio_estado, llamada, mail, nota, etc.)
- estado_anterior: text
- estado_nuevo: text
- detalle: text
- metadatos: jsonb
- created_at: timestamptz

RECORDATORIOS (Seguimientos programados)
----------------------------------------
- id: uuid (PK)
- presupuesto_id: uuid (FK → presupuestos)
- usuario_id: uuid (FK → users)
- titulo: text
- descripcion: text
- fecha_recordatorio: timestamptz
- tipo_accion: text (llamada, mail, visita, seguimiento, revision, otro)
- estado: text (pendiente, cumplido, vencido, cancelado)
- completado_en: timestamptz
- notas_finalizacion: text
- created_at: timestamptz
- updated_at: timestamptz

PRODUCTOS (Catálogo de productos)
---------------------------------
- id: uuid (PK)
- codigo: text (unique)
- nombre: text
- descripcion: text
- precio_base: numeric
- moneda: text
- categoria: text
- imagen_url: text
- activo: boolean
- created_at: timestamptz
- updated_at: timestamptz

DISCOUNT_REQUESTS (Solicitudes de descuento)
--------------------------------------------
- id: uuid (PK)
- presupuesto_id: uuid (FK → presupuestos)
- solicitante_id: uuid (FK → users)
- descuento_solicitado: numeric
- justificacion: text
- estado: text (pendiente, aprobada, rechazada)
- aprobador_id: uuid (FK → users)
- fecha_respuesta: timestamptz
- comentario_aprobador: text
- created_at: timestamptz

COMMISSIONS (Comisiones)
------------------------
- id: uuid (PK)
- vendedor_id: uuid (FK → users)
- presupuesto_id: uuid (FK → presupuestos)
- monto_venta: numeric
- porcentaje_comision: numeric
- monto_comision: numeric
- estado: text
- fecha_calculo: timestamptz
- created_at: timestamptz

4.2. ÍNDICES
------------

Performance optimizado con índices en:
- presupuesto_actividad: por presupuesto_id, usuario_id, tipo_evento
- recordatorios: por usuario_id, fecha_recordatorio, estado
- presupuestos: por vendedor_id, estado, created_at
- presupuesto_items: por presupuesto_id
- productos: por codigo, categoria, activo

4.3. TRIGGERS AUTOMÁTICOS
--------------------------

1. trigger_presupuesto_creado
   → Al crear presupuesto, registra evento "creado" en actividad

2. trigger_presupuesto_cambio_estado
   → Al cambiar estado, registra evento "cambio_estado"

3. trigger_recordatorios_updated
   → Actualiza campo updated_at al modificar recordatorio

4. trigger_generate_presupuesto_code
   → Genera código único automático (ej: PRES-2025-0001)

5. trigger_actualizar_comisiones
   → Calcula comisión al facturar presupuesto

4.4. FUNCIONES DE BASE DE DATOS
--------------------------------

actualizar_recordatorios_vencidos()
→ Cambia estado a "vencido" de recordatorios pendientes que pasaron su fecha

generate_presupuesto_code()
→ Genera código secuencial único

calculate_commission()
→ Calcula monto de comisión según configuración

4.5. ROW LEVEL SECURITY (RLS)
------------------------------

POLÍTICAS PRINCIPALES:

Users:
- Admins ven todos
- Vendedores solo ven su propio perfil

Presupuestos:
- Admins ven todos
- Vendedores solo los suyos
- Solo pueden editar los propios en estado BORRADOR

Presupuesto_actividad:
- Admins ven todo
- Vendedores solo actividades de sus presupuestos
- Pueden insertar en sus propios presupuestos

Recordatorios:
- Admins ven todos
- Vendedores solo los suyos
- Pueden gestionar sus propios recordatorios

Productos:
- Todos pueden ver (si activo=true)
- Solo admins pueden crear/editar/eliminar

Discount_requests:
- Vendedores ven las suyas
- Admins ven todas
- Solo admins pueden aprobar/rechazar

7. FLUJOS DE TRABAJO
================================================================================

7.1. FLUJO: CREAR PRESUPUESTO
------------------------------

1. Vendedor ingresa al sistema
2. Click en "Nuevo Presupuesto"
3. Completa datos del cliente
4. Agrega items (productos o descripción manual)
5. Sistema calcula totales automáticamente
6. Agrega imágenes (opcional)
7. Guarda como BORRADOR
8. Sistema genera código único (ej: PRES-2025-0001)
9. Sistema registra evento "creado" en actividad

VALIDACIONES:
- Cliente nombre es requerido
- Al menos 1 item es requerido
- Precios deben ser > 0
- Descuento no puede ser > 100%

7.2. FLUJO: PRESENTAR PRESUPUESTO
----------------------------------

1. Vendedor abre presupuesto en estado BORRADOR
2. Revisa información
3. Click en "Presentar"
4. Sistema valida datos completos

10. SEGURIDAD Y PERMISOS
================================================================================

10.1. AUTENTICACIÓN
-------------------

MÉTODO:
- Email + Password
- Sesiones manejadas por Supabase Auth
- JWT tokens
- Refresh tokens automáticos

CONTRASEÑAS:
- Hasheadas con bcrypt
- No se almacenan en texto plano
- Reseteo vía email

10.2. AUTORIZACIÓN (RLS)
------------------------

ROW LEVEL SECURITY (RLS):
Cada tabla tiene políticas que controlan:
- Quién puede ver datos (SELECT)
- Quién puede insertar (INSERT)
- Quién puede actualizar (UPDATE)
- Quién puede eliminar (DELETE)

REGLAS PRINCIPALES:

VENDEDORES:
✓ Ven solo sus propios presupuestos
✓ Pueden crear presupuestos
✓ Pueden editar solo BORRADORES propios
✓ Ven solo sus actividades y recordatorios
✓ Pueden crear actividades en sus presupuestos
✓ Ven todo el catálogo (productos activos)
✓ NO pueden editar productos
✓ Pueden solicitar descuentos
✓ NO pueden aprobar descuentos

ADMINISTRADORES:
✓ Ven todos los presupuestos
✓ Pueden editar cualquier presupuesto
✓ Ven todas las actividades
✓ Pueden crear actividades en cualquier presupuesto
✓ Gestionan catálogo completo
✓ Gestionan usuarios
✓ Aprueban/rechazan descuentos
✓ Acceso completo a reportes

10.3. AUDITORÍA
---------------

TRAZABILIDAD:
- Cada acción queda registrada
- Tabla presupuesto_actividad registra:
  - Quién hizo la acción (usuario_id)
  - Qué acción (tipo_evento)
  - Cuándo (created_at)
  - Detalles (detalle, metadatos)

EVENTOS AUDITADOS:
- Creación de presupuesto
- Cambios de estado
- Ediciones
- Eliminaciones (soft delete)
- Solicitudes de descuento
- Aprobaciones/rechazos
- Llamadas y seguimientos

INTEGRIDAD:
- No se pueden eliminar registros de auditoría
- Timeline es inmutable
- Solo admins pueden ver auditoría completa

10.4. PROTECCIÓN DE DATOS
--------------------------

DATOS SENSIBLES:
- Contraseñas: hasheadas
- Emails de clientes: protegidos por RLS
- Datos de presupuestos: solo accesibles por owner y admins

SOFT DELETE:
- Presupuestos eliminados no se borran
- Se marca campo deleted_at
- Quedan en BD para auditoría
- No aparecen en listados normales

BACKUPS:
- Supabase hace backup automático diario
- Punto de restauración disponible

10.5. MEJORES PRÁCTICAS DE SEGURIDAD
-------------------------------------

✓ NUNCA COMPARTAS CONTRASEÑAS
  Cada usuario debe tener su propio acceso.

✓ CAMBIA CONTRASEÑA TEMPORAL
  Al recibir usuario nuevo, cambia la contraseña inmediatamente.

✓ DESACTIVA USUARIOS QUE SE VAN
  No elimines, desactiva para mantener historial.

✓ REVISA LOGS REGULARMENTE
  Identifica accesos sospechosos.

✓ CAPACITA EN SEGURIDAD
  Todos deben entender importancia de proteger datos.

✓ NO EXPONGAS CREDENCIALES
  No envíes contraseñas por WhatsApp o email no cifrado.

2. Verificar políticas RLS del bucket

1. Verificar rango de fechas seleccionado

3. Verificar filtros aplicados

2. Revisar permisos del navegador para descargas

14. PREGUNTAS FRECUENTES
================================================================================

Q: ¿Puedo editar un presupuesto después de presentarlo?
A: No directamente. Una vez presentado, el presupuesto está "congelado"
   para mantener trazabilidad. Si necesitas modificarlo:
   1. Clónalo
   2. Haz las modificaciones
   3. Presenta el nuevo
   4. Anula el anterior

Q: ¿Cómo puedo ver presupuestos de otros vendedores?
A: Solo administradores pueden ver presupuestos de todos.
   Vendedores solo ven los propios.

Q: ¿Los clientes pueden ver sus presupuestos en el sistema?
A: No. Este sistema es interno. Los clientes reciben PDFs por email.
   No tienen acceso al sistema.

Q: ¿Puedo eliminar un presupuesto?
A: Sí, pero es "soft delete". El presupuesto se marca como eliminado
   pero queda en base de datos para auditoría.

Q: ¿Cómo se calculan las comisiones?
A: Automáticamente al marcar presupuesto como FACTURADO.
   Se aplica % configurado para cada vendedor sobre el monto final.

Q: ¿Puedo personalizar las plantillas de PDF?
A: Actualmente hay 2 plantillas (HDM y Corporate).
   Para personalizaciones adicionales, se requiere desarrollo.

Q: ¿El sistema funciona en móvil?
A: Sí, es responsive y funciona en navegadores móviles.
   Sin embargo, la experiencia óptima es en desktop.

Q: ¿Puedo cambiar el logo de los PDFs?
A: Sí, modificando los archivos en src/services/pdfGenerator*.ts

Q: ¿Cómo agrego un nuevo tipo de actividad al timeline?
A: Requiere modificar:
   1. Enum en tabla presupuesto_actividad (migration)
   2. Tipo TipoEvento en actividadesService.ts
   3. Iconos y colores en TimelinePresupuesto.tsx

Q: ¿Los recordatorios se envían por email?
A: No automáticamente. Aparecen en el sistema cuando el vendedor
   ingresa. Para emails automáticos se requiere configurar cron job
   con la Edge Function discount-reminders.

Q: ¿Puedo exportar a PDF?
A: Los presupuestos se exportan a PDF individualmente.
   Los reportes se exportan a Excel.

Q: ¿Cómo recupero una contraseña olvidada?
A: El administrador puede resetear tu contraseña desde el panel
   de Usuarios. Recibirás un email con nueva contraseña temporal.

Q: ¿Puedo tener más de un administrador?
A: Sí, puedes crear múltiples usuarios con rol "admin".

Q: ¿Los datos están seguros?
A: Sí, el sistema usa:
   - Autenticación segura (JWT)
   - Row Level Security (RLS)
   - Encriptación en tránsito (HTTPS)
   - Backups automáticos diarios

Q: ¿Qué pasa si se va la luz mientras trabajo?
A: Los datos se guardan en el servidor al hacer click en "Guardar".
   Si no guardaste antes de perder conexión, los cambios se pierden.
   Se recomienda guardar frecuentemente.

Q: ¿Puedo trabajar offline?
A: No, el sistema requiere conexión a internet para funcionar.

Q: ¿Cuántos usuarios puedo tener?
A: Ilimitados en el sistema. Las limitaciones dependen del plan
   de Supabase contratado.

Q: ¿El sistema tiene límites de almacenamiento?
A: Depende del plan de Supabase:
   - Plan gratuito: 500MB
   - Plan Pro: 8GB
   - Plan superiores: más

15. GLOSARIO DE TÉRMINOS
================================================================================

ACTIVIDAD:
  Evento registrado en el timeline de un presupuesto.
  Ejemplos: llamada, email, cambio de estado, nota.

ADMIN/ADMINISTRADOR:
  Usuario con permisos completos. Puede gestionar usuarios,
  aprobar descuentos, ver reportes de todos, etc.

AUDITORÍA:
  Registro histórico de todas las acciones en el sistema.
  Permite rastrear quién hizo qué y cuándo.

BORRADOR:
  Estado inicial de un presupuesto. Está en creación,
  puede editarse libremente.

CATÁLOGO:
  Lista de productos/servicios disponibles para cotizar.
  Facilita la creación de presupuestos.

COMISIÓN:
  Porcentaje del monto de venta que se paga al vendedor.
  Se calcula automáticamente al facturar.

CONVERSIÓN:
  Relación entre presupuestos en una etapa y la siguiente.
  Ejemplo: "Conversión de aceptación" = Aceptados / Presentados

DASHBOARD:
  Pantalla principal que muestra resumen e indicadores clave.
  Cada rol tiene su dashboard personalizado.

DÍAS SIN MOVIMIENTO:
  Cantidad de días desde la última actividad registrada
  en un presupuesto. Indica si requiere seguimiento.

EDGE FUNCTION:
  Función serverless que se ejecuta en la nube.
  Ejemplos: enviar email, crear usuario, recordatorios.

ESTADO:
  Etapa del ciclo de vida de un presupuesto.
  Estados: Borrador, Presentado, Aceptado, Facturado, Anulado.

EXPORTACIÓN:
  Descarga de datos del sistema en formato Excel o TXT
  para análisis offline.

FACTURADO:
  Estado final de un presupuesto exitoso. Indica que
  se generó factura y se concretó la venta.

IVA:
  Impuesto al Valor Agregado. Se calcula automáticamente
  según la configuración (ej: 10% en Paraguay).

JWT (JSON Web Token):
  Token de autenticación que identifica al usuario
  en cada petición al servidor.

KPI (Key Performance Indicator):
  Indicador clave de performance. Métricas que miden
  éxito o eficiencia. Ejemplos: tasa de conversión,
  ticket promedio, monto facturado.

PIPELINE:
  Embudo o flujo de presupuestos. Vista que muestra
  cuántos presupuestos hay en cada estado.

PRESENTADO:
  Estado de presupuesto enviado al cliente. Esperando
  respuesta. Ya no puede editarse.

PRESUPUESTO:
  Cotización o propuesta comercial. Documento que detalla
  productos/servicios ofrecidos y su precio.

RLS (Row Level Security):
  Sistema de seguridad que controla qué filas de datos
  puede ver/editar cada usuario según su rol.

RECORDATORIO:
  Alerta programada para realizar una acción futura.
  Ejemplos: "Llamar al cliente en 3 días".

SEGUIMIENTO:
  Actividades registradas para mantener contacto con
  el cliente y avanzar el presupuesto.

SOFT DELETE:
  Eliminación lógica (no física). El registro se marca
  como eliminado pero permanece en base de datos.

SUPABASE:
  Plataforma de base de datos y backend utilizada.
  Alternativa open-source a Firebase.

TICKET PROMEDIO:
  Monto promedio de cada presupuesto. Se calcula dividiendo
  monto total entre cantidad de presupuestos.

TIMELINE:
  Línea de tiempo que muestra cronológicamente todas
  las actividades de un presupuesto.

TRIGGER:
  Acción automática que se ejecuta cuando ocurre un
  evento en base de datos. Ejemplos: registrar actividad
  al cambiar estado.

VENDEDOR:
  Usuario que crea y gestiona presupuestos. Tiene acceso
  limitado solo a sus propios datos.

VENCIDO:
  Recordatorio que pasó su fecha sin ser completado.

VIGENCIA:
  Cantidad de días que un presupuesto permanece válido
  antes de que los precios puedan cambiar.
